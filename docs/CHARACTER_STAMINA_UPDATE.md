# 每次選角、對手體力與湖畔匹克鵝

基底：AGV 修正版 `f6ad658`。開發分支：`task/codex/character-stamina-lake`。

## 行為

- 訪客、完整登入、已存資料的快速進入，都先顯示「今天想用誰上場」。上次角色只保留為設定，不能跳過這次選擇；選好並確認後才進中興湖。
- 人偶、匹克鵝、黑天鵝皆可選，能力相同。個人設定、手機選單與原先角色按鈕可再次更換。選角期間暫停球場與鍵盤操作。
- 個人設定展示台使用交付的匹克鵝 GLB，可拖曳轉身；手機窄畫面改為上下排版。
- 對手體力依這一分的來回拍數消耗，**包含發球、雙方各一次擊球各算一拍**。新手 8、中等 18、困難 30、果蠅 24 拍；第 5 關至少 30，第 7 關至少 36 拍。
- 歸零後逐步增加撞網／出界機會，移速降至 72%；不是立即判輸。沿用球體運動、落點、掛網及原本計分流程；下一分 `resetServe()` 恢復 100%。這是遊戲平衡數值，並非人體生理模型。
- 中興湖新增同一隻 GLB 匹克鵝的骨架舞步：側步、轉肩、擺手、交替屈膝。是閃身步風格的程式動畫，沒有宣稱影片逐幀動作捕捉。
- 設定展示與湖畔角色各限制至約 20 FPS、DPR 上限 1.25、不開陰影。離開湖畔／關閉展示時釋放其 renderer 與模型資源；模型來源 bytes 可重用。

## 實際檢查

已用 390 × 844 桌面瀏覽器檢查三種進入流程、強制選角與 Escape 保護、設定／手機換角、匹克鵝展示及湖畔載入。沒有橫向頁面溢出。

Node 檢查各難度體力邊界、歸零後失誤機率增長、換分恢復。瀏覽器另外以測試狀態及固定亂數重現：新手第 8 拍後，電腦產生掛網方向的球速，更新 lastHitter／來回拍數，保持原計分流程；重設發球後恢復 100%。該項是程式狀態注入測試，不是人工實打八拍。

執行 `node scripts/build-single.js`、`git diff --check`。未反覆跑與本次無關的後端資料測試。手機效能與遊玩手感仍由使用者實機確認。

## 給 AGV

先從此測試分支取用，保留 `character-portrait.js`、`opponent-stamina.js` 在模板與單檔打包的順序。`beginCharacterEntry()` 是所有登入入口的共同出口；請勿重新直接呼叫 switchStage 而跳過選角。
